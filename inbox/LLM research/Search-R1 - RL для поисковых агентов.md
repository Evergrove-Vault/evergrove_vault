# 📝 Overview
**Search-R1** учит модель **сама формулировать поисковые запросы по ходу рассуждения** с помощью обучения с подкреплением (RL): модель чередует «подумала → поискала → подумала», а награда зависит только от итогового ответа. В отличие от промптовых агентов, стратегия поиска *выучивается*. Родственные работы: DeepResearcher (RL в реальном вебе), эмпирический разбор дизайна таких агентов и SLCA-GRPO (как правильно раздавать награду).

> [!important] Чего нет в моих заметках
> В [[reasonin методы построения размышлений модели]] есть ReAct, Self-Ask, CoT+RAG — все они *промптовые*. Заметка [[agentic RAG]] пустая, а [[Microsoft AI Introduces CoRAG]] содержит только ссылку. Линии «агент обучен искать» в волте нет.

# 💡 Как это работает
- Основа — RL-обучение рассуждающих моделей в духе DeepSeek-R1 (в статье сравниваются методы оптимизации RL): модель генерирует рассуждение, при необходимости выдаёт поисковый запрос, получает результаты, продолжает; цикл повторяется несколько раз.
- **Маскирование найденных токенов** при вычислении потерь — возвращённый поиском текст не «учится» как сгенерированный, что стабилизирует RL.
- **Простая outcome-награда**: правильность финального ответа (например, точное совпадение). Промежуточных наград за поиск нет.
- Итог по статье: на семи QA-наборах +41% (Qwen2.5-7B) и +20% (Qwen2.5-3B) относительно разных RAG-baselines при одинаковых условиях; код и чекпойнты открыты ([PeterGriffinJin/Search-R1](https://github.com/PeterGriffinJin/Search-R1)).

**Эмпирический разбор** ([arXiv:2505.15117](https://arxiv.org/abs/2505.15117)): формат-награды помогают итоговому качеству, а промежуточные награды за поиск влияют слабо; масштаб и инициализация модели (обычная против «рассуждающей») сильно влияют на исход RL; выбор поискового движка сильно определяет динамику обучения и устойчивость агента при выводе.

**DeepResearcher** ([arXiv:2504.03160](https://arxiv.org/abs/2504.03160)): RL не на фиксированном корпусе, а в *реальном вебе* (с ограничениями API, разнообразием страниц и защитой от парсинга); мульти-агентная схема, где браузерные агенты извлекают информацию со страниц. По статье, до +28,9 пункта над промптовыми базами и до +7,2 над RL-агентами на «контролируемом RAG»; у обученных агентов наблюдаются планирование, перекрёстная проверка источников, самокоррекция и честное «не нашёл».

**Награда по сегментам:** если усреднять награду по всей траектории, шум финального текста «протекает» в решения о вызове инструментов — [[SLCA-GRPO - сегментное распределение награды]].

# ⚠️ Ограничения
- Обучение требует инфраструктуры RL и поискового бэкенда; результаты чувствительны к выбору поискового движка.
- Метрики — точность ответов на QA-наборах; для длинных отчётов (deep research) такие бенчмарки менее показательны.
- Это метод *обучения* модели, а не готовая надстройка над существующим RAG. Для использования без обучения остаются промптовые схемы ([[GPT Researcher]]).

# 🧭 Где встроить в HUB RAG
Группа «reasoning»: рядом с ReAct и Reflexion ([[reasonin методы построения размышлений модели#🔹 5. ReAct (Reason + Act)]]) появляется вариант «политика поиска, обученная RL». Он частично заменяет и «предобработку запроса» (Multi-Query, Decomposition — модель сама решает, что искать), и правило «поискать ещё» из Self-Correction.
