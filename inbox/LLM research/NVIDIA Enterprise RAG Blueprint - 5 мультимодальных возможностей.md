# 📝 Overview
NVIDIA описывает референс-архитектуру **Enterprise RAG Blueprint** как набор из пяти возможностей, которые подключаются **по очереди** и оцениваются по качеству, задержке и стоимости. Полезнее всего не сами возможности (большинство знакомы), а **таблицы**: они показывают, что ни одна из них не даёт выигрыша на всех данных.

> [!important] Что уже есть и чего не хватает
> Декомпозиция запроса и фильтры по метаданным в волте уже описаны ([[building the Entire RAG Ecosystem and Optimizing Every Component#Decomposition]], [[building the Entire RAG Ecosystem and Optimizing Every Component#Query Structuring]]). Нового здесь: (1) извлечение таблиц, диаграмм и инфографики на этапе индексации, (2) шаг визуального рассуждения по найденным картинкам, (3) числа «до/после» по наборам данных и (4) сама идея измерять каждую опцию отдельно.

# 💡 Пять возможностей
1. **Базовый мультимодальный конвейер** — NeMo Retriever извлекает текст, таблицы, диаграммы, графики и инфографику, эмбеддит, ищет и реранкает; ответ — LLM Nemotron. Самая эффективная по цене и задержке конфигурация.
2. **Reasoning** — включённые рассуждения модели по найденным свидетельствам. Пример из статьи: коэффициент операционного денежного потока Adobe за 2017 год без рассуждений посчитан как 2,91, с ними — верно, 0,83.
3. **Декомпозиция запроса** — подзапросы, поиск по каждому, сборка ответа; добавляет вызовы LLM (задержка и цена).
4. **Фильтрация по метаданным** — автор, дата, категория, теги безопасности; фильтр-выражения строятся автоматически из вопроса. Заявлено: сужает пространство поиска на 50% и даёт 100% precision на целевых доменах.
5. **Визуальное рассуждение** — VLM (Nemotron Nano 2 VL, 12B) интерпретирует картинки, диаграммы и инфографику; увеличивает задержку.

# 📊 Точность по наборам данных (из таблиц статьи)
| Набор | База (таблица 1) | + Reasoning (табл. 2) | + Декомпозиция (табл. 3) |
|---|---|---|---|
| RAG Battle (мультимодальный) | 0,809 | 0,85 | 0,854 |
| KG RAG (мультимодальный) | 0,565 | 0,58 | — |
| FinanceBench (мультимодальный) | 0,633 | **0,69** | 0,631 |
| BO767 (мультимодальный) | 0,910 | 0,88 ↓ | 0,885 ↓ |
| HotpotQA (текст) | 0,671 | — | **0,725** |
| Google Frames (мультимодальный) | 0,509 | — | **0,600** |

Авторы пишут о среднем приросте reasoning около 5%; но на BO767 и reasoning, и декомпозиция *ухудшают* результат, а на FinanceBench декомпозиция ничего не даёт. Выигрыш декомпозиции — на многошаговых наборах (HotpotQA, Frames).

# ⚠️ Выводы для практики
- Опции надо включать по одной и мерить на *своём* наборе вопросов ([[оценка качества RAG]], [[ragas]]): NVIDIA использует RAGAS.
- Декомпозиция и reasoning нужны маршрутизатору: включать только для многошаговых вопросов — [[retrieval#Routing Retrieval]], [[Адаптивный retrieval - Adaptive-RAG, FLARE, Self-Route]].
- Числа получены на наборах NVIDIA с их моделями; блог вендора.
- В обновлении блюпринта также заявлены «документ-уровневая суммаризация» (мелкая и глубокая стратегии) и каталог данных для управления корпусами.
