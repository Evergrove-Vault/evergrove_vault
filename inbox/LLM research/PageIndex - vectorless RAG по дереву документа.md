# 📝 Overview
**PageIndex** — «vectorless, reasoning-based RAG»: PDF превращается в **дерево «оглавления»** (заголовки, диапазоны страниц, сводки, вложенные разделы), а LLM **сама ходит по дереву**, выбирая разделы и страницы, — без векторной БД и без нарезки на чанки. Ответ сопровождается точными ссылками на страницы. **PageIndex Flash** (26.08.2026) — быстрый локальный движок построения дерева для PDF с текстовым слоем.

> [!important] Чего нет в моих заметках
> В [[building the Entire RAG Ecosystem and Optimizing Every Component#Hierarchical Indexing (RAPTOR) Knowledge Tree]] иерархия строится из *сводок чанков* и всё равно ищется по эмбеддингам. Здесь иерархия — настоящая структура документа, а поиск — *рассуждение* LLM по этой структуре; эмбеддингов нет вообще. Такого подхода (и вообще «RAG без векторов») в canvas нет.

---

# 💡 Как это работает
1. **Индексация.** Flash читает разметку самого PDF (заголовки, разделы, номера страниц) вместо того, чтобы просить vision-модель угадывать структуру. Получается дерево: «titles, page ranges, summaries, and nested sections» — «a table of contents optimized for LLM search». Работает локально.
2. **Поиск.** LLM получает дерево, решает, какой раздел открыть, читает нужные страницы, при необходимости идёт глубже или возвращается — так, как человек листает оглавление ([[agentic RAG]] в чистом виде).
3. **Результат.** Ответ с ссылками на разделы и страницы; контекст использует историю диалога.

# 📊 Заявленные цифры
- Индексация ≈ **$0,001 за страницу**; на документах от 9 до 1098 страниц — от 13 секунд до 4,5 минуты.
- Бенчмарк PageIndex OSS: 62 вопроса-поиска фактов по 34 PDF, 1945 страниц (из MMLongBench-Doc-V2); качество растёт с размером модели и «усилием рассуждения».
- Подача PDF в модель целиком в 2,1 раза дороже поиска через PageIndex на 52 страницах и в 16,6 раза дороже на 420; после ≈800 страниц PDF уже не помещается в контекст.
- README проекта: 98,7% на FinanceBench (система Mafin 2.5 на PageIndex) против ≈50% у векторного RAG — это заявление вендора, не независимая проверка.

# ⚠️ Ограничения
- **Только PDF с текстовым слоем** для локального Flash: OCR нет; сканы и насыщенные картинками файлы обрабатывает облачная версия.
- Бенчмарк Flash — вопросы, ответ на которые стоит в сплошном тексте («every answer is a fact stated in running text»): это не проверяет сложную агрегацию по документам.
- Каждый запрос — несколько LLM-вызовов, цена растёт с числом шагов рассуждения. Это мой вывод: в блоге Flash сравнения по цене и задержке с векторным поиском нет, есть только сравнение с подачей PDF целиком.
- В блоге Flash не описан поиск *между* сотнями документов: дерево строится на один документ, выбор нужного документа (метаданные, сводки) придётся решать отдельно.
