# 📝 Overview
**Docling** — открытый инструментарий IBM Research (лицензия MIT), который превращает PDF, DOCX и другие форматы в **единое богато структурированное представление**: заголовки, абзацы, таблицы, рисунки, порядок чтения. Работает на двух специализированных моделях: **DocLayNet** (анализ разметки страницы) и **TableFormer** (структура таблиц), запускается на обычном оборудовании, есть Python API и CLI; интегрирован с LangChain, LlamaIndex и spaCy.

> [!important] Чего нет в моих заметках
> Все 21 способ в [[21 Chunking Strategies for RAG]] предполагают, что структура документа уже есть (страницы, разделы, таблицы). Откуда она берётся — не сказано: [[pyMuPDF (fitz)]] пока пустая заметка, [[Ollama-OCR]] отвечает только за распознавание текста. Слой «PDF → структура» — самая ненадёжная часть пайплайна и в canvas вообще отсутствует.

# 💡 Что даёт слой layout-aware парсинга
- **Разметка страницы** (DocLayNet): модель детекции объектов классифицирует блоки — текст, заголовок, таблица, рисунок, подпись.
- **Таблицы** (TableFormer): восстанавливает строки, столбцы, заголовки, объединённые ячейки даже без границ; результат можно отдать как Markdown или JSON — это предпосылка для [[21 Chunking Strategies for RAG#13. Table-aware chunking]].
- **Порядок чтения и иерархия** — основа для структурной нарезки ([[21 Chunking Strategies for RAG#6. Page-based chunking]], нарезка по разделам) и для деревьев документа как в [[PageIndex - vectorless RAG по дереву документа]].
- **Единый формат** на выходе позволяет менять парсер, не переписывая chunking.
- По описаниям в обзорах, работает локально: модели скачиваются при первом запуске, дальше без сети, ключи API не нужны.

Статья фиксирует популярность инструмента: 10 тыс. звёзд на GitHub меньше чем за месяц, №1 trending репозиторий GitHub в ноябре 2024.

# ⚠️ Ограничения
- По сравнению с «плоским» извлечением текста добавляются модели разметки и таблиц. Авторы заявляют, что они работают на обычном оборудовании с небольшим бюджетом ресурсов, но на больших корпусах время обработки стоит измерить самому.
- Для сканов нужен OCR (по обзорам, Docling его включает; в аннотации статьи OCR не упоминается). Для документов, смысл которых — в макете и картинках, лучше подходит поиск по образам страниц ([[ColPali - поиск по картинкам страниц]]).
- В статье нет собственных сравнительных замеров качества RAG с и без Docling; выбор парсера стоит подтверждать на своих документах по метрикам [[оценка качества RAG]].
